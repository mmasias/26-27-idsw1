# Farmear Aura: Iteración 1

He podido analizar que en mi modelo de dominio inicial había una limitacion. Esa limitacion nace con la siguiente pregunta: **¿Que proceso ocurre para que una persona termine teniendo aura?**
 

### Inicio
A una **persona** le ocurre una situación\
↓\
La **persona** reacciona\
↓\
Muestra/Manifiesta una **actitud**\
↓\
El **publico** observa su **actitud**\
↓\
El **publico** interpreta su **actitud**\
↓\
¿A el **publico** le genera respeto/admiracion?\
↓\
Si la respuesta es SI -> Se le atribuye **aura** a **persona** \
Si la respuesta es NO -> No se le atribuye **aura** a **persona**
\
\
\
 
Dado este diagrama de actividades, podemos pensar que este proceso podría ocurrir sin que la persona estuviera intentando que el publico le atribuyese aura. Por lo que aqui entra el concepto de *farmear* que no aplicamos anteriormente y es totalmente indispensable. Cuando hablamos de *farmear* hablamos de intencionalidad, es decir, la persona quiere generar una determinada percepcion en el publico. Esto lo logra manifestando una actitud/gesto/baile/movimiento que trate de causar un efecto de respeto/admiración.\
Además, para la creacion del diagrama vamos a adoptar el lenguaje del cliente cosa que no hicimos en el modelo inicial.
